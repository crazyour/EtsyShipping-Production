# EtsyShipping 网页版

参照原 Windows WPF 3.0.2 客户端的浏览器工作台。布局和业务分组来自原安装包 MainWindow、AdminCenterWindow 与 BusinessSettingsCenterWindow 资源；使用原版深蓝公司标题栏、浅灰导航、紧凑表格和列表 / 详情分栏。

`dist/` 是静态页面，`api/bridge.js` 是 Vercel Node Function；本地 `server.mjs` 使用同一个转发函数。网页演练数据保存在当前浏览器；真实生产数据仍由原生产服务器保存和授权。

## 已实现的网页流程

- 订单助手：图片上传、拖放、预览、本机保存，文本规则提取、CSV 批量导入与模板下载。
- 我的订单：新建、编辑、详情、搜索、状态 / 店铺 / 国家筛选、分页、多选、CSV 导出、复核、SKU 绑定、批量复核及错误订单归档。
- 待选择物流：订单摘要、物流方案、发货仓库、重量 / 目的国校验、发货草稿，创建 DEMO 演练单号并生成仓库任务。
- 仓库：任务领取、拣货、称重、打印确认、交运状态流转，输入 / 扫描任务号查找；拣货单和演练标签预览及系统打印。
- 物流：详情、人工轨迹、异常记录、签收、演练取消；已交运包裹不允许直接取消。
- Etsy 人工回填：复制承运商和追踪信息、人工确认记录；不会自动调用 Etsy。
- 业务设置：店铺、仓库发件资料、物流方案、SKU 与申报模板、打印模板、价格版本的创建、编辑、启停、导出，价格 CSV 导入。
- 高级管理：演练成员角色和范围、物流账号配置元数据、真实连接诊断、操作日志、备份导出 / 恢复、Synthetic 数据清理。
- 经营看板、客户统计、响应式手机布局、对话框键盘操作。

以上履约写入功能属于网页演练工作区，不是原生产系统的写接口。另有独立的管理员 Etsy 云端订单同步模块（见下文），只读取订单，不下物流单、不回填 Etsy。AI、真实面单、真实物流下单 / 取消、真实业务成员权限和密码重置仍需接通生产后端。

演练订单和配置使用 localStorage；演练图片使用 IndexedDB。刷新保留数据，但不同设备不共享。同源同浏览器的演练使用者共享工作区。JSON 备份不包含图片原件。演练运费以 CNY 记录；订单金额按原币种分别统计，不进行隐式汇率转换。真实 Etsy 同步订单独立加密保存于服务端 Redis，不进入演练工作区、浏览器持久存储或演练备份。

## 业务操作流程

这套工作台用于把店铺订单整理为可发货资料，经人工复核、选择物流、仓库处理后，记录平台回填与物流结果。以下步骤描述当前网页演练工作区的实际操作；不会向物流商下真实订单，也不会自动更新 Etsy。

### 1. 准备基础资料

在“业务设置”中确认店铺、发货仓库、SKU 与申报资料、物流方案和打印模板已配置并启用。物流方案需要覆盖订单目的国和包裹重量范围。首次体验可以使用已有演练资料；配置店铺或物流账号信息不代表已经完成外部服务授权。

### 2. 录入订单资料

进入“订单助手”，按资料来源选择录入方式：

- 图片资料：分别上传“订单截图”和“产品辨认图”，用于留档、人工核对和拣货参考。点击“根据所选资料建单”，填写订单表单并关联所选图片；当前不会自动识别图片内容。
- 文本资料：点击“粘贴文本 / 提取字段”，通过文本规则提取部分字段，在订单表单中检查并补全。
- 批量资料：先“下载 CSV 模板”，按模板填写，再通过“CSV 导入订单”批量建单。
- 无现成资料：点击“手工新建订单”，直接填写。

核对店铺、平台订单号、收件人、地址、国家、商品、数量、金额、币种及预估重量后保存。订单进入“我的订单”，状态为“待复核”。同一店铺不能重复录入相同的平台订单号。

### 3. 复核订单并绑定 SKU

在“我的订单”中打开订单，检查收件资料与商品信息，选择已启用的 SKU，点击“确认复核”。符合条件的订单也可以批量复核。完成后订单变为“待选物流”。

如需修改资料，应在进入仓库前编辑；编辑保存后会重新进入“待复核”，需要再次确认。

### 4. 选择物流并创建演练物流单

进入“待选择物流”，选中订单并点击“准备发货”，选择物流方案、发货仓库，填写包裹重量与演练运费。系统校验目的国、渠道重量上限及仓库是否启用。

确认创建后，生成 `DEMO` 开头的演练追踪号和一条“待领取”仓库任务，订单变为“仓库处理中”。此时物流单为“待交运”，不代表已向真实物流商购买面单或交寄包裹。

### 5. 仓库拣货、称重、打印与交运

在“仓库与打印”中查找任务，也可输入或扫描任务号定位。仓库任务按以下顺序推进：

```text
待领取 → 拣货中 → 待称重 → 待打印 → 待交运 → 已交运
```

领取后由领取人继续处理；完成拣货后录入大于零的实际重量，再预览并打印所需单据或演练标签。打开打印窗口不会自动视为打印完成，需人工确认已打印，才能进入“待交运”。最后确认演练交运。

交运后，订单变为“已发货”，物流单变为“运输中”，并生成 Etsy“待回填”记录。演练标签不能作为真实物流面单使用。

### 6. Etsy 人工回填与物流跟踪

交运后有两项后续工作，可分别处理，不需要等待签收才回填：

- “Etsy 人工回填”：查看、复制承运商和追踪信息，并记录人工回填确认，状态从“待回填”变为“已回填”。当前仅演练这一流程，不能把 `DEMO` 单号填到真实 Etsy 订单；网页上的确认也不会调用 Etsy 接口。
- “物流状态”：人工录入物流事件、地点及处理结果，记录“运输中”“运输异常”或“已签收”。这些状态只允许在仓库交运后记录，当前没有物流商自动轨迹同步。签收更新的是物流单状态，订单仍为“已发货”。

### 7. 异常处理与数据留存

- 尚未交运但物流方案选错：填写原因取消演练物流单，关联仓库任务同时取消，订单退回“待选物流”，可重新选择方案。
- 已交运后出现问题：不能直接取消物流单，应在物流记录中登记异常和处理结果；当前没有真实拦截或退件接口。
- 错误订单：可使用归档功能保留记录；存在有效物流单关联时不能直接归档。
- 日常核查：通过经营看板、客户统计及操作日志查看处理情况；按需导出 CSV 或在高级管理中导出 JSON 备份。图片原件需另行保留，清除浏览器站点数据会丢失本机工作区。

## 本地启动

需要 Node.js 18 或更新版本。双击 `启动 EtsyShipping.command`，或运行 `npm start`，然后打开 <http://127.0.0.1:4188>。

本地演练账号为 `admin` / `admin`，可以编辑浏览器工作区，不具备生产权限。Vercel 关闭免登录演练入口，站点管理员通过 `SITE_ADMIN_USERNAME` / `SITE_ADMIN_PASSWORD` 验证后进入演练工作区；生产账号使用原服务器登录。

## 发布到 Vercel

1. 将此文件夹作为项目根目录导入 Vercel，框架选 **Other**。若提交的是包含本文件夹的仓库，将 Root Directory 设为 `EtsyShipping-Mac-Web`。
2. `vercel.json` 已配置构建检查、`dist` 静态输出和 `/api/bridge` Function。无需配置数据库、持久磁盘或额外 NPM 依赖。
3. 默认上游是 `https://shipping.sunfacework.com`。如服务器地址不同，在 Vercel 项目环境变量中设置 `ETSY_SERVER_URL`，值为可从 Vercel 访问的 HTTPS 服务根地址，然后重新部署。请勿在项目或浏览器代码中填写真实账号、密码或 API 密钥。
4. 如需开启 Vercel 站点演练管理员，设置 `SITE_ADMIN_USERNAME` 和 `SITE_ADMIN_PASSWORD`。凭据只在服务端验证，登录后可操作浏览器演练工作区，不会获得原生产服务器权限。
5. 发布后访问 `/api/bridge?route=meta`，应返回 JSON 且 `demoEnabled` 为 `false`。访问 `/api/bridge?route=runtime` 应返回生产服务状态；如果是 502，需先修复原服务器或网络连通性。
6. 用原生产账号测试登录和只读页面。若网站包含真实订单及客户数据，发布前应按团队要求设置访问权限和域名。

也可以在此目录运行 `npx vercel` 创建预览部署，确认后运行 `npx vercel --prod` 发布生产版本。首次使用需要先登录 Vercel CLI。当前 Mac 上直接输入 `vercel` 会调用同名的 Python 程序，因此请使用 `npx vercel`。

## 安全与运行范围

### 管理员在网页配置服务器

入口：使用站点管理员登录后，进入「高级管理 → 服务器配置（管理员）」。即使数据库和加密密钥尚未配置，此入口仍可显示；普通生产账号、浏览器演练角色以及未经服务端验证的本地演练登录不能获得此权限。

1. 将含此功能的版本部署到当前 Vercel 项目的 **Production** 环境。已有 `SITE_ADMIN_USERNAME` / `SITE_ADMIN_PASSWORD` 仍用于确认管理员身份，不会被这个页面修改。
2. 在页面重新输入管理员密码，并填写临时 Vercel Token。Token 需有当前团队 / 项目的环境变量读取和写入权限；不要把 Token 发到聊天或提交到仓库。
3. 点击「检查已保存配置」，查看哪些配置尚未填写。检查只返回是否已保存、是否被当前部署加载，不回显任何密钥值。
4. 补全缺失的加密密钥、Upstash REST URL、Upstash 读写 Token、正式网站源地址。新数据库可用「生成随机密钥」生成 32 字节随机密钥，并通过「复制密钥备份」自行保存到密码管理器；恢复已有数据库必须使用原加密密钥，不要生成新密钥。
5. 勾选备份与目标确认，点击「保存到 Vercel（需重新部署）」。后台仅新增当前项目的 Production 环境变量，不覆盖已存在的配置。
6. 打开 Vercel 重新部署，再登录网站配置 Etsy 店铺。**保存不会修改当前函数进程的环境，也不会自动重新部署。** 若提示部分成功或结果不确定，先检查已保存配置；不要直接重新生成密钥再提交。

该入口调用 Vercel 官方 API，临时 Vercel Token 只在当次请求中用于鉴权，不写入环境变量、数据库、localStorage、sessionStorage 或演练备份；提交后清空表单中的 Token 和管理员密码。新设置以 Vercel `sensitive` 环境变量保存。网站不会创建 Upstash 数据库，也不声称已验证数据库实际可用性。

安全边界：

- `POST /api/bridge?route=admin-server-config` 每次重新验证站点管理员密码、同源请求和 Vercel Token 对目标项目的权限；不依赖尚未初始化的 Redis 会话。初始配置权限不授予真实订单读取权限。
- 写入项目 / 团队固定绑定于 `lib/server-setup.mjs` 中本项目的部署标识，且必须与 Vercel 运行时的 `VERCEL_PROJECT_ID` 一致。浏览器不能指定项目、团队、接口地址、任意变量名或目标环境。仅允许表格中的四项业务配置，不接受修改管理员密码或保存 Vercel Token。
- 本地、预览部署和项目标识不匹配时禁止写入正式配置。如果提示系统环境变量缺失，请在 Vercel 项目中开启 **Automatically expose System Environment Variables** 并重新部署；若迁移到另一个项目，须先核对并更新服务端部署绑定，不能在网页随意切换目标。
- 已配置变量，包括 Vercel 已保存但尚未重新部署的变量，均不覆盖。创建请求不使用 `upsert`，并发初始化冲突由 Vercel 拒绝。通过团队共享变量接口按当前项目筛选检查；若项目关联共享环境变量，或 Token 无权检查共享配置，本入口停止写入，避免遮蔽共享配置。配置过程中不要同时在 Vercel 修改或关联环境变量。
- 首次初始化使用进程内每 15 分钟 30 次的补充限流；这不是跨实例防暴力破解保证。数据库配置完整后，还会应用已有的跨实例管理员验证限流。保留 `admin / admin` 仍有风险，Vercel Token 是独立的高权限凭据，请使用短有效期 Token，并在完成后撤销；不要在不可信的网站输入。
- 不回传 Vercel 原始错误、请求体或环境变量值。API 返回部分成功、超时或无法确认结果时，不自动重试保存，不宣称全部成功。

实现依据 [Vercel 环境变量写入 API](https://vercel.com/docs/rest-api/projects/create-one-or-more-environment-variables)、[环境变量查询 API](https://vercel.com/docs/rest-api/projects/retrieve-the-environment-variables-of-a-project-by-id-or-name)、[官方 SDK 共享变量接口](https://github.com/vercel/sdk/blob/main/src/funcs/environmentListSharedEnvVariable.ts) 与 [系统环境变量](https://vercel.com/docs/environment-variables/system-environment-variables)。配置和权限采用模拟服务测试；实际 Token 和线上配置仍须由管理员在正式网站填写。

### 仅管理员配置 Etsy API

“高级管理 → Etsy API 配置（管理员）”仅向经过服务端验证的站点管理员开放。默认管理员**用户名仍为 `admin`**，以 `SITE_ADMIN_USERNAME` 的配置为准；浏览器演练成员的角色、用户名或生产服务器的普通登录令牌均不能授予此权限。

- 每家店可保存 Shop ID、显示名称、应用 Keystring / Shared Secret，并修改或停用配置（最多 100 家）。修改时密钥不回显，留空保留原凭据；更换时须同时填写两项。
- GET / POST `/api/bridge?route=admin-etsy-config` 都验证服务端管理员会话。前端隐藏入口不是权限边界；手动调用接口也不能绕过。
- 会话使用 15 分钟有效的 HttpOnly、SameSite=Strict Cookie；Vercel 上另加 Secure。退出或切换到普通账号会撤销会话；更换管理员密码使旧会话失效。配置写入有跨站请求检查和并发版本校验。
- 密钥使用 AES-256-GCM 加密后写入 Upstash Redis，不进入 localStorage、sessionStorage、浏览器工作区备份或 API 列表响应。列表仅返回配置状态和最近修改人 / 时间。
- 按用户要求，不强制密码长度或复杂度，允许保留 `admin / admin`。这会增加公网管理员账号被猜中、真实订单和店铺授权被滥用的风险；建议使用强密码。启用此功能仍需在服务端配置以下环境变量并重新部署：

| 环境变量 | 用途 |
| --- | --- |
| `SITE_ADMIN_USERNAME` | 管理员用户名，默认 `admin` |
| `SITE_ADMIN_PASSWORD` | 管理员登录密码，不能为空；不强制长度、复杂度或排除 `admin`，仍建议使用随机强密码 |
| `ETSY_CONFIG_ENCRYPTION_KEY` | 随机 32 字节密钥的标准 Base64 编码；须妥善备份，不能随意替换，否则旧配置无法解密 |
| `UPSTASH_REDIS_REST_URL` | 已创建的 Upstash Redis HTTPS REST 根地址 |
| `UPSTASH_REDIS_REST_TOKEN` | 对应数据库的服务端读写令牌，不是只读令牌 |
| `SITE_PUBLIC_ORIGIN` | OAuth 必填，正式 HTTPS 网站源地址，如 `https://etsyshipping.vercel.app`，不要带路径或尾部斜杠 |

存储、加密密钥或管理员密码缺失时，系统关闭真实 API 配置权限，不退回浏览器保存。管理员登录在启用安全配置后进行跨实例限流：全站每 15 分钟最多 30 次尝试。正式站建议另外启用部署平台的访问防护。

### 一键同步 Etsy 真实订单

入口：「我的订单」或「高级管理」→「Etsy 订单同步」。这是独立的服务器订单列表，不写入浏览器演练订单，也不上传到原 `shipping.sunfacework.com` 后端。

首次准备：

1. 部署上述环境变量。按用户要求，没有自动修改 `admin / admin`，也不再因密码强度锁定真实授权和同步；服务端存储、加密密钥和管理员身份验证仍为必需。
2. 在 Etsy 应用管理中登记精确的回调地址：`https://你的正式域名/etsy-callback.html`。应用须具有对应店铺的有效访问权限，不能通过本系统绕过 Etsy 的应用审批或店铺数量限制。
3. 在「Etsy API 配置（管理员）」逐店保存 Shop ID、名称、应用凭据，点击「官方授权」，由店主在 Etsy 完成授权，然后启用店铺。仅申请 `transactions_r` 读取权限。
4. 回调验证 PKCE、一次性 state、管理员会话、配置版本，并核对授权 Etsy 用户确为该 Shop ID 的店主。令牌仅在服务端加密存储，不返回浏览器；临近过期自动刷新。更换应用凭据会清除旧授权，必须重新授权。

日常操作：点击一次「一键同步所有店铺」，页面自动驱动服务端分批读取订单、获取商品图片链接、去重并加密保存。无需下载文件，也无需手工上传。

- 默认首次同步近 30 天有更新的订单，后续从上次成功同步时间前 5 分钟开始增量取单。可填写起始日期补取历史；这是**最后修改日期**范围，不是仅按下单日期筛选。查询终点固定为本轮开始时间。
- 包含付款、未付款、已发货、取消等 Etsy 返回的状态，不隐式过滤；仅保存资料，不执行付款、发货、退款或自动复核。
- 停用店铺不参加；未授权店铺标为跳过。逐店显示读取进度、新增、更新、未变化、资料缺失数量与错误。一个店铺失败不会使其他店铺的已保存订单丢失。
- 分页每次读取 10 笔，图片逐项匹配；同一个 Etsy 商品明细的 `listing_id + listing_image_id` 决定对应图片，不会按文件名猜配。
- `Shop ID + receipt ID` 是唯一键。重复点击不会创建第二个进行中的任务；重复取到相同订单不会重复入库。已有订单只用不早于当前更新时间的资料更新，且订单与任务进度原子保存。
- 单店所有分页处理成功后才推进同步时间；分页数量或顺序发生变化会停止该店，并提示重试，避免标记不完整同步为成功。重试失败店铺从原范围重新读取并去重；已成功店铺不重跑。
- 限流和暂时故障按 `Retry-After` 自动等待，最多连续重试 3 次，再显示失败。刷新页面可读取服务端进度；任务由网页请求推进，**不是 Cron 后台常驻任务**，关闭页面、导航离开或管理员会话过期会停止后续批次。重新登录后点击「继续未完成同步」即可继续；「暂停」会等待当前请求结束。
- 真实订单页面仅管理员可读取，跨设备须使用管理员登录；不会自动授予演练仓库成员权限，也不会自动创建物流、仓库或回填任务。
- 收件人、地址、金额和商品规格保留 Etsy 原文。地址、邮箱等可能因 Etsy 权限或地区政策不返回；缺失会显示提示，不生成虚假数据。暂不读取买家邮箱，电话号码也不会猜测填入。
- 图片保存 Etsy 返回的 `i.etsystatic.com` HTTPS 商品图片链接并显示预览，**不下载原图备份，不包含聊天附件或买家定制稿**。图片删除或权限不足时显示缺失提示；不影响其余有效订单保存。
- 「导出本页（英文 CSV）」严格沿用所给模板的 18 列，不增加图片列。每订单一行，总额只计一次；多商品以 SKU / 明细 ID 标明颜色、尺寸，图片链接写入 `notes`。仅导出当前 25 笔；真实商品名、姓名和地址不翻译。

新增接口均由管理员 HttpOnly 会话保护：POST `etsy-authorize`、`etsy-callback`、`etsy-sync-start`、`etsy-sync-step`、`etsy-sync-retry`，GET `etsy-sync-status`、`etsy-cloud-orders`（通过 `/api/bridge?route=...` 访问）。写操作执行同源检查。配置编辑、令牌刷新、授权保存和同步步骤使用跨实例锁；敏感配置、任务中间数据和订单均以 AES-256-GCM 加密存储。

部署函数执行上限设为 60 秒，每个步骤最多执行少量有超时的请求；不在函数中长时间睡眠等待限流。服务器 Redis 数据需单独备份、监控容量与费用；没有自动配置数据删除期限、数据库备份或数据库服务套餐。不要随意替换加密密钥。

验证：`npm run build` 执行语法与自动化测试。`test/etsy-cloud.test.mjs` 用模拟 Etsy / Redis 检验权限、OAuth、分页、去重、限流和增量续传；`test/etsy-cloud-browser.mjs` 检查按钮流程、刷新续传、手机排版、导出、权限与登出清理。模拟测试不代表实际店铺已授权；上线验收仍需真实应用、持久存储和至少一家店主授权。

接口实现依据 Etsy 官方的 [OAuth / PKCE](https://developers.etsy.com/documentation/essentials/authentication/)、[请求规范](https://developers.etsy.com/documentation/essentials/requests/)、[限流说明](https://developers.etsy.com/documentation/essentials/rate-limits/) 与 [OpenAPI 定义](https://www.etsy.com/openapi/generated/oas/3.0.0.json)。

存储适配依据 [Upstash REST API](https://upstash.com/docs/redis/features/restapi)，没有自动创建数据库、修改线上密码或发布新版本。首次启用需由部署管理员设置上述环境变量。

### 其他安全边界

- 网站只允许已列出的原系统 API 路径，不接受任意转发 URL；上游必须是 HTTPS。
- 密码仅用于登录或改密请求，不写入磁盘。Access Token 仅保存在当前标签页的 `sessionStorage`；刷新令牌不持久化。
- 转发请求与静态文件都不缓存；超时、上游不可用、非 JSON 响应会返回可读错误。
- 生产模式已接入登录、首次改密、退出、运行状态、仪表盘、订单、物流异常、仓库任务等只读接口。新增业务操作在演练模式运行；生产模式不会把本地记录当作服务器结果。
- 如果原生产服务器不可用或 API 契约与原客户端不同，Vercel 站点仍可加载，但真实登录与业务数据无法正常使用；需修复上游后再验收。

运行 `npm run build` 可检查语法并测试身份转发、完整履约状态机、数据校验、存储回滚、并发冲突和 CSV。Vercel 构建时运行同一检查。

浏览器验收脚本 `test/browser-flow.mjs` 使用已有 Playwright 环境，设置 `PLAYWRIGHT_MODULE`（可选 `CHROMIUM_PATH`）后运行 `node test/browser-flow.mjs`，默认测试地址 `http://127.0.0.1:4190`。截图保存至被 Git 忽略的 `test-output/`。脚本只操作隔离的浏览器测试上下文。
